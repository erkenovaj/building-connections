# Гипотезы и эксперименты: curriculum RL для Connections

Дата: 2026-07-11
Статус: draft к созвону

## TL;DR

Пайплайн probe → STaR SFT → agentic GRPO с curriculum 2→3→4 категории уже собран и
проверен на Qwen3-1.7B (LoRA, Kaggle). Главный блокер: base Qwen3-1.7B на 2-cat досках
выигрывает ~0 эпизодов — GRPO нечего усиливать, а STaR не из чего собирать датасет.
Основная ставка следующего раунда: **скейл модели (4B/8B) + полный fine-tuning** даст
ненулевой base win@k, и тогда весь curriculum заработает. Проверяется дёшево (probe),
а дорогие 12–36ч раны запускаются только после положительного probe.

## Что уже есть (предыдущие результаты)

1. **Bandit GRPO (grpo_connections.py, Qwen2.5-0.5B / Qwen3-1.7B LoRA).**
   Плотная частичная награда за k=2/k=3 угаданных элементов создавала локальные
   оптимумы: модель училась собирать "почти правильные" группы вместо победы.
   Чинили итеративно (см. историю коммитов), в итоге ушли на терминальную награду
   за весь эпизод: `R = 1·[won] − 0.25·mistakes − 0.02·tool_calls`.

2. **Gen-config баг (этап 0).** `max_new_tokens=256` обрезал Qwen3 посреди `<think>`
   → valid_rate 0.0. Исправлено (commit `0a90d49`), probe теперь репортит
   `truncated_gen_rate` — обязательная метрика для всех дальнейших ранов.

3. **Base probe Qwen3-1.7B, 2-cat.** win@k probe (unbiased estimator, как pass@k из
   Codex-статьи arXiv:2107.03374): seeds 1,000,000+ дают 0/4, 0/4 побед, по 16 ошибок
   на доску. То есть даже на минимальной curriculum-ступени базовая 1.7B не выигрывает.
   Это и есть мотивация скейла.

4. **Инфраструктура готова и протестирована:** rollout driver с `env_mask`
   (env-токены исключены из лосса), терминальная награда, win@k probe с `--out-boards`,
   STaR sample/train, agentic GRPO через TRL 1.7.0 `rollout_func`, difficulty ordering
   по эмпирическому win-rate, curriculum-ноутбук с гейтами (win@1 ≥ 0.05 чтобы стартовать
   GRPO, ≥ 0.6 чтобы перейти на следующий размер доски).

## Связь со статьями

- **STaR (Zelikman et al., arXiv:2203.14465).** Rejection-sampling SFT: сэмплируем
  эпизоды, оставляем только выигранные траектории (с `<think>`), учим на них.
  Ключевое ограничение STaR — нужен ненулевой base success rate, иначе датасет пуст.
  Ровно наша ситуация с 1.7B → аргумент за скейл.
- **DeepSeekMath / GRPO (arXiv:2402.03300).** Group-relative advantage: если все
  8 генераций на доску проиграли, advantage нулевой — градиента нет ("zero-grad
  camping"). Отсюда гейт win@1 ≥ 0.05 перед стартом GRPO.
- **DeepSeek-R1 (arXiv:2501.12948).** Cold-start SFT перед RL стабилизирует
  и ускоряет — наш STaR-этап это оно же, только данные self-generated.
- **DFT (arXiv:2508.05629).** Per-token CE, взвешенный на sg(p): вместо равномерного
  NLL сильнее учит токены, где модель уже уверена. Заявка статьи — лучшая
  генерализация на reasoning-данных, чем NLL. Предложение ментора — сравнить
  на нашем STaR-датасете (в TRL встроено, `loss_type="dft"`).
- **LoRA vs full FT (Biderman et al., arXiv:2405.09673 "LoRA Learns Less and
  Forgets Less").** LoRA r=16 ограничивает ёмкость дообучения; для RL, где нужно
  выучить новое поведение (recovery после ошибки), полный FT ожидаемо сильнее.
  Пока фандинга нет, но кластер есть — окно проверить full FT на 4–8B.

## Гипотезы

### H1 — скейл: у 4B/8B ненулевой base win@k на 2-cat

**Почему:** reasoning-способности Qwen3 растут со скейлом; 1.7B даёт 0 побед,
но и близко к границе — задача 2-cat (8 слов, 2 группы) не выглядит невозможной.
**Проверка:** win@k probe base-моделей (E1). Дёшево, до суток на все.
**Хотим увидеть:** win@8 > 0 хотя бы на 2-cat у 4B; лучше — win@1 ≥ 0.05.
**Если нет:** проблема не в масштабе — смотреть промпт/формат/no-think режим,
либо few-shot в системный промпт; GRPO-раны не запускать.

### H2 — full FT > LoRA при том же скейле

**Почему:** RL учит новое поведение, LoRA r=16 — узкое место ёмкости (H2 ← Biderman).
**Проверка:** E5 (опционально): 1.7B LoRA vs 1.7B full FT на идентичном пайплайне.
Дешёвая изоляция эффекта, но вторична — главные раны E2/E3 сразу full FT.
**Хотим увидеть:** full FT даёт выше win@1 после STaR и быстрее растущий reward EMA
в GRPO при тех же данных.

### H3 — STaR warm-start необходим перед GRPO

**Почему:** GRPO усиливает существующие успехи (см. связь со статьями). При win@1 < 0.05
почти все группы генераций без побед → нулевой advantage → шум вместо обучения.
**Проверка:** встроена в пайплайн как гейт: probe → если win@1 < 0.05 → STaR → re-probe.
**Хотим увидеть:** после STaR win@1 растёт кратно (типично для rejection sampling
на задачах с ненулевым base rate); GRPO стартует с ненулевым advantage.

### H4 — DFT ≥ NLL на STaR-данных (сравнение для ментора)

**Почему:** заявка arXiv:2508.05629; наши данные — reasoning-траектории, профиль тот же.
**Проверка:** E4: два SFT-рана на одном датасете, отличие только `--dft`; сравнить
win@k после SFT и после последующего GRPO.
**Хотим увидеть:** DFT ≥ NLL по win@1 после SFT; если loss у DFT плоский — поднять
lr до 2e-5 (замечание ментора).

### H5 — curriculum + отбор лёгких досок ускоряет обучение

**Почему:** прямой RL на 4-cat при win ~0 не работает (H3); 2→3→4 с гейтом win@1 ≥ 0.6
даёт на каждой ступени ненулевой сигнал. Отбор досок по эмпирическому win-rate
(probe `--out-boards` → `load_seed_order`) — вариант предложения ментора про
difficulty estimator, без внешних данных.
**Проверка:** сам пайплайн; логируем win@1 по ступеням.
**Хотим увидеть:** прохождение гейтов 2-cat → 3-cat за бюджет рана; win@1 на 4-cat > 0
к концу. Полный проход до 0.6 на 4-cat — stretch goal, не критерий провала.

### H6 — терминальная награда без shaping не ловит локальные оптимумы

**Почему:** проверено на bandit-этапе: частичный кредит порождал reward hacking.
**Проверка:** пассивно — мониторим в GRPO-ранах mean mistakes и reward-разложение;
если модель "фармит" короткие проигрыши, будет видно.
**Хотим увидеть:** reward EMA растёт за счёт доли побед, а не за счёт минимизации
tool_calls.

## Эксперименты: что конкретно запускать

Все раны — через новый `train/pipeline.py` (конфиг YAML + bash, см. таск-док),
логи в comet-ml + локальный JSONL, state.json для резюма по ступеням.

| #   | Что                                                         | Модель          | Режим     | Бюджет | Гейт на запуск                        |
| --- | ----------------------------------------------------------- | --------------- | --------- | ------ | ------------------------------------- |
| E0  | smoke: полный пайплайн, крошечные числа                     | Qwen3-0.6B/1.7B | LoRA      | <1ч    | —                                     |
| E1  | base win@k probe, 2/3/4-cat, 16 досок × 8 эпизодов          | 1.7B, 4B, 8B    | inference | часы   | —                                     |
| E2  | полный пайплайн: probe → STaR(NLL) → GRPO, curriculum 2→3→4 | Qwen3-4B        | full FT   | 12–24ч | E1: 4B win@8 > 0 на 2-cat             |
| E3  | то же                                                       | Qwen3-8B        | full FT   | 24–36ч | E1: 8B win@8 > 0; E2 не упал по инфре |
| E4  | ветка DFT: STaR train с `--dft`, дальше тот же GRPO         | Qwen3-4B        | full FT   | 12–24ч | тот же датасет, что E2                |
| E5  | (опц.) изоляция full FT: LoRA vs full на одном скейле       | Qwen3-1.7B      | оба       | ~12ч   | E1: 1.7B win@8 > 0 хоть где-то        |

Порядок: E0 → E1 → (E2 ∥ E4, датасет общий) → E3. E5 — если останется бюджет.

**Память (ориентир, 1×80GB):** 8B full FT = bf16 веса+грады ~32GB + 8-bit Adam
(`adamw_bnb_8bit`) ~16GB + активации с gradient checkpointing
→ ~60GB, помещается. 4B — с запасом. Multi-GPU/FSDP сознательно не делаем, пока
не известно железо (отдельная работа, особенно rollout_func под FSDP).

## Что хотим увидеть (метрики и критерии)

Логируется на каждой ступени:

- **probe:** win@1/win@4/win@8, boards_with_any_win, mean_mistakes, mean_tool_calls,
  mean_episode_reward, truncated_gen_rate (должен быть ~0, иначе поднять max_new_tokens)
- **STaR sample:** kept/played (доля выигранных траекторий)
- **SFT:** loss-кривая (у DFT следить за плоскостью)
- **GRPO:** reward mean/EMA, KL, completion length, frac_zero_advantage групп

Картина успеха: base win@k(8B) > win@k(4B) > 0 на 2-cat (H1) → после STaR win@1
кратно выше base (H3) → GRPO reward EMA растёт и win@1 на held-out (seeds 2,000,000+)
пробивает 0.6 → переход на 3-cat, паттерн повторяется. DFT-ветка на равных или
лучше NLL (H4).

Картина провала и что она значит:

- E1 всё по нулям даже на 8B → дело в постановке/промпте, не в скейле; RL не запускать,
  вернуться к формату задачи.
- STaR kept-rate < 1–2% → датасет слишком мал; поднять temperature/эпизодов на доску
  или сузить пул до самых лёгких досок.
- GRPO reward EMA плоский при win@1 ≥ 0.05 → смотреть frac_zero_advantage и
  num_generations (поднять с 8), потом lr.
